# 《弹壳特工队》活动并列发车平台设计规范 (Design Spec)

## 1. 项目背景与设计目标

### 1.1 背景
手游《弹壳特工队》（Survivor.io）定期开放各类排行榜活动（如钓鱼、游乐园、大富翁等）。该类活动的排行榜机制支持“积分相同并列第一，全员共享最高一档奖励”。

游戏内的奖励档位（如 106 分及以上档可获得史诗配件 + 10把钥匙）吸引大量玩家寻求并列合作。活动通常每日刷新结算（如每日 00:00 至 24:00 为单轮）。

### 1.2 系统目标
打造一个专注于《弹壳特工队》玩家活动的 **网页协同与发车平台 (Web App)**：
- **组织协调**：帮助创作者/管理员统一发布每日发车班次（按时间、目标积分档位分组）。
- **微信导流**：提供微信授权登录、微信群二维码展示、游戏内统一头像暗号指示。
- **契约锁定**：一键微信快捷登录，强制绑定游戏ID与游戏昵称，预约成功后锁定当前班次，防止无故跳车破坏队伍稳定性。
- **高精度卡点**：提供精确到秒/毫秒的发车倒计时引擎与声光提醒。

## 2. 系统核心功能与规则规范

### 2.1 用户认证与身份约束模块
1. **微信 OAuth 2.0 快捷登录**：
   - 在微信内置浏览器打开网页时，自动引导授权快捷登录，获取唯一 `OpenID`、微信头像及微信昵称。
2. **游戏资料绑定**：
   - 用户首次登录需绑定：`游戏玩家ID`（全网唯一校验）与 `游戏昵称`。
   - 玩家仅可修改自己账号下的游戏昵称与游戏ID。

### 2.2 创作者/管理员后台 (Admin Dashboard)
1. **班次管理与参数设置**：
   - 创作者可灵活发布不同时间段的班次（如 `01:05 凌晨第一弹`、`08:05 上班族班`、`21:05 晚间班`）。
   - **动态目标积分档位**：创作者可配置当前活动对应的奖励档位，如 `106分`（史诗配件+10钥匙最高档）、`66分`（精配件档）等。
   - **参数包含**：发车日期轮次（如 2026-07-25）、发车精确时间、招募名额上限（如 200人）、目标积分、统一游戏头像指示图、微信群二维码图片、班次规则说明。
2. **后台可视化监测**：
   - 实时查看各班次报名人数、名额状态及全套玩家名单（微信头像、游戏昵称、游戏ID）。

### 2.3 玩家班次大厅与严格锁定规则
1. **每日班次大厅**：
   - 展示当日所有发车班次卡片（发车时间、剩余名额、目标分档位 106分、统一头像图标）。
   - 班次列表中明细展示已报名玩家的 `游戏昵称` 与 `游戏ID`。
2. **预约锁死逻辑（Strict Locking）**：
   - 玩家在确认预约某班次后，系统将其 `User_ID` 与该 `Batch_ID` 强绑定。
   - **硬锁定原则**：一旦预约成功，不可主动退车或更换其他班次，以确保团队发车人数的稳定与诚信契约。
   - **单轮单班**：每个真实玩家账号在单日活动轮次中仅可预约一个班次。

### 2.4 车厢卡点大厅与高精度计时
1. **精确到秒的发车倒计时引擎**：
   - 基于 `performance.now()` 高精度时钟，提供大字号倒计时（`HH:MM:SS.ms`）。
   - 发车前 10 秒黄色预警，最后 5 秒播放倒计时音效与语音提示（“5、4、3、2、1，立即进入游戏！”）。
2. **社群与战术暗号集成**：
   - 展示该班次专属微信群二维码（支持放大与长按识别）。
   - 展示该班次要求的**游戏内统一更换头像图解**（以便玩家在游戏内排行榜识别战友）。
3. **混入路人即作废与重新排队机制 (Auto Invalid & Re-queue)**：
   - 发车后，如果发现小组内混入了路人（例如有未在网页匹配的陌生玩家进入同一小组，或有人分数超出预设目标）：
   - 玩家点击【本组有路人，直接作废】，该小车厢即刻判定为 `[已作废]`。无需任何复杂的播报流程。
   - 系统**自动解除该小组内玩家的锁定限制**，玩家可以直接点击【重新排队】，预约下一个新的发车班次。

## 3. 技术架构与设计要求

### 3.1 前端设计 (Frontend)
- **极致视觉**：采用现代深色系游戏风（Dark Theme + Glassmorphism 玻璃拟态 + 金黄色金刚石质感强调色）。
- **响应式 UI**：完美适配 iPhone / Android 微信内置浏览器及 PC 端的屏幕宽度。
- **动画动效**：卡片悬浮 hover 效果、发车倒计时数字翻牌/光晕动效。

### 3.2 模拟与后端数据规范
- **用户模型 (User)**: `id`, `openId`, `wechatName`, `wechatAvatar`, `gameId`, `gameNickname`
- **班次模型 (Batch)**: `id`, `date`, `time`, `targetScore`, `maxCapacity`, `currentCount`, `avatarUrl`, `qrCodeUrl`, `notice`, `status`
- **预约模型 (Booking)**: `id`, `userId`, `batchId`, `createdAt`, `status`
